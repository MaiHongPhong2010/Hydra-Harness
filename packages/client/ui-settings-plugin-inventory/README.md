# @hydraharness/harness-client-ui-settings-plugin-inventory

The local Web Settings contribution for OpenAI/Codex plugin bundles. It registers **Plugins**, **Skills**, and **Marketplace** tabs in the existing Plugins section, and contributes its imported-hook catalog to that section's **Hooks** tab through `settings.plugins.hooks.item`. Remote clients only receive the Plugins tab with an unavailable message; local controls are loopback-only.

The cross-package source-of-truth matrix and Codex compatibility boundary are in the [Settings Plugins ownership and Codex compatibility note](../../../.agents/notes/implemented/architecture/2026-09-14-settings-plugins-ownership-and-codex-compatibility.md).

**Plugins** lists native Hydra deployment plugins together with every imported OpenAI/Codex bundle and its enablement/remove controls: one list of everything the agent can use. Native entries with the same module share one card but retain separate switches for their Host or preset instances. Enablement switches stage drafts until **Save plugin settings** commits all edited native and imported entries. Ordinary Host rows apply on Save; core rows display a restart warning and remain running until the app restarts. Saved and unsaved changes remain highlighted while they differ from app startup, including after Settings closes and reopens. **Discard changes** restores saved states without clearing the startup comparison. A partial save retains failed and unsubmitted edits for retry; successful entries stay saved. Preset rows identify their preset, show **Session-scoped**, and apply only to new sessions; this host-wide inventory does not report whether any individual session has loaded that preset. Explicitly grouped native modules share a control and an expandable module list; runtime-owned entries without independent persistence show their ownership instead of a disabled switch. Imported plugin names are unique across sources, and removing the installed record permits that name to be imported from another source. **Marketplace** only manages sources: it adds, validates, lists, enables/disables, and removes OpenAI/Codex marketplace sources. The add dialog is two steps in one pass: the source is saved first, and then a named plugin is staged into the Hydra home through the same import call the Plugins tab's list reflects. A blank name saves the source alone; a failed install leaves the source saved, reports the failure as an import result beside the staged name, and its retry re-runs only the import — never re-adding an already-saved source. Toggling a marketplace's slot cascades enable/disable to every plugin imported from it; removing a marketplace uninstalls those plugins. **Skills** lists imported skills. The imported-hook catalog lists imported hook declarations and owns their trust/revoke action; it renders inside the shared **Hooks** tab, below the user's own hook records, rather than as a tab of its own. The existing **MCP** tab, contributed by `ui-settings-plugins`, owns imported MCP server enablement and renders each discovered tool's `ask`/`allow`/`deny` approval override. The loopback-only Host Remote accepts the displayed public tool name as well as the raw MCP name and persists the override with the imported runtime state; the server's default mode remains the fallback for tools without an override.

The installed Plugins view uses a compact table with type, runtime status, enablement, and pending-change indicators. Filters and sorting stay in the toolbar; selecting a row opens a centered document-level dialog with a read-only details table for the plugin's description, intended application, Cordis phase, preset/session scope, related instances, and restart requirements while row controls remain the single place for changes. Description and application text comes from the native package manifest or imported plugin manifest through Host projections. A global core warning summarizes restart-pending changes, and the Save/Discard footer appears only while drafts or save errors need action.

Marketplace sources accept GitHub shorthand, HTTPS/SSH Git URLs, or local roots. The Host accepts `.agents/plugins/marketplace.json` and root `marketplace.json`. The Settings contribution reads snapshots on first selection and whenever its tab becomes active again, so imports and marketplace cascades appear when returning to a visited tab. Marketplace enablement and removal wait until imported plugin drafts are saved or discarded, preventing a later Plugins-tab Save from reversing a marketplace cascade or targeting a removed identity. Hidden tabs retain local drafts; displayed records come from Host reads and operation results.

**Marketplace-owner grouping.** The Plugins, Skills, and Marketplace tabs and the imported-hook catalog each split their rows into one section per marketplace owner, derived by `marketplace-owner.ts`'s `marketplaceOwnerLabel()`: the path segment right after the domain (`https://github.com/example-labs/toolkit` groups as `example-labs`, containing `Toolkit`). GitHub shorthand and scp-style Git sources resolve the same owner; a local marketplace root, which has no owner, falls back to its own folder name. An imported plugin's group key is its `source.marketplace` when it came from a marketplace, or its own `source.source` otherwise, so directly-imported plugins each get their own single-plugin group.

**Shared search.** `ui-settings-plugins` renders the one search box for the whole Plugins section (see its README); every surface here receives the current text as the `query` owner prop — from the `settings.plugins.tab` slot for the tabs, and forwarded through `settings.plugins.hooks.item` for the imported-hook catalog — and filters its own rows against plugin/skill/hook/marketplace-source text, independent of which tab is active.

Settings lists and edits the global preset plugin configuration. Workspace preset and enablement overrides come from project files. Host plugin installation, core controls, imported bundles, and marketplace sources share the same global Settings panel.

## Model Experience

None, as this package only visualizes Host-owned plugin state and registers no model-facing input.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- Core plugin state takes effect after restart, and preset plugin state affects only new sessions.
- The Skills tab reads the session-scoped native catalog when a session is selected; without one it reports that state explicitly.
